Production Infrastructure

Claude Code as a Service, deployed via Docker and Coolify.

I needed a production API that could generate social media copy for new content automatically, without API costs and without a human in the loop. Instead of calling the Anthropic API directly, I built a FastAPI + Celery service that runs the Claude Code CLI via subprocess inside Docker containers, deployed via Coolify.

Claude writes output to a temp file as structured JSON. FastAPI reads it, validates against a Pydantic schema, and retries automatically on schema failure. It is launched anytime content goes live.

services/claude_worker.py 
# app.py — FastAPI wrapping Claude Code CLI
MAX_RETRIES = 3

def call_claude_to_file(prompt, schema, model=None):
    output_path = f"/tmp/claude_{uuid.uuid4().hex}.json"
    full_prompt = f"{prompt}\n\nWrite JSON to: {output_path}\nFields: {schema}"
    result = subprocess.run(
        ["claude", "-p", full_prompt, "--dangerously-skip-permissions"],
        env={**os.environ, "CLAUDE_CODE_OAUTH_TOKEN": token},
        capture_output=True, text=True, timeout=60,
    )
    if result.returncode != 0:
        raise HTTPException(status_code=502, detail=result.stderr)
    return json.loads(Path(output_path).read_text())


@app.post("/social/copy", response_model=SocialCopyResponse)
def social_copy(req: SocialCopyRequest,
                api_key: str = Security(verify_api_key)):
    last_err = HTTPException(status_code=502, detail="All retries failed")
    for attempt in range(1, MAX_RETRIES + 1):
        try:
            data = call_claude_to_file(req.prompt, SCHEMA)
            return SocialCopyResponse(**data)  # 200
        except ValidationError as e:
            last_err = HTTPException(422, str(e))
        except HTTPException as e:
            last_err = e
    raise last_err  # 502 after 3 attempts
Content Pipeline

Autonomous content generation pipeline.

Publishes 6+ articles a day across 15 categories with zero human intervention. 1,000+ published and compounding. Here is every stage.

1
Content Planning
A quota engine fires every two hours, compares the publish log against the cadence target, and writes only the deficit. Missed fires catch up; nothing double-publishes. Seasonal and holiday calendars feed topic selection; a category-matched author profile sets the voice.
2
Generation
Claude generates the draft using a write-time prompt protocol that embeds the author's voice rubric directly into the system prompt. Per-author structural patterns are enforced before generation starts.
3
Anti-LLM Validation (18 checks)
Output runs through 18 validators before it is allowed to proceed. Catches patterns that make content sound generated rather than written.
em-dashes banned phrases (50+) staccato patterns orphaned micro-sentences passive overuse missing contractions transition word stacking hedging language listicle structure uniform sentence length
4
Voice Scoring
Content is scored across 10 dimensions against the author's profile: warmth, formality, vocabulary complexity, sentence rhythm, personal anecdote density, and more. Pieces below the threshold are regenerated.
5
Approval Gate
Validator pass + voice score above a hard threshold = approved. Failed pieces get up to two rewrite passes with failure context added to the prompt, then are parked with an alert. Below-bar content never ships, and no human reviews individual pieces.
6
Publish
Approved content is written to the Django backend via internal API. Metadata, author attribution, category tags, and publication timestamp are set programmatically.
7
ISR Revalidation + Verify
Cloudflare cache and Next.js ISR are invalidated for the new content path, making the piece live without a full rebuild. A post-publish check then confirms the article is in the search index and its canonical URL returns 200; failures quarantine loudly instead of vanishing.
LLM-Powered ETL

100,000+ records regenerated with a local model.

A national resource directory, built by machine: a VPN-rotated scraper fleet collects the raw data, an ETL pipeline parses and rewrites every listing to surface structured information (IEP support, therapy programs, enrollment requirements), and 17,000+ listings are live because of it.

100k+
records processed with two-phase validation and idempotent skip logic

A local Qwen/Ollama model handles regeneration, no API cost at scale. Two-phase validation runs structural screening before the LLM call and a full schema + content hash check after. The --batch flag and per-record skip logic make the pipeline safe to interrupt and resume.

Onboarding a new data source is a scaffold command on each side of the seam (scraper-new → parser-new): dispatch and retry sweeps derive from a category registry, so there are no hand-maintained wiring lists to forget. Anti-bot retries are bounded per source, and 20+ Poetry CLI scripts handle orchestration, reporting, and partial reruns.

Autonomous Operations

The platform runs itself and pages me when it can't.

Every unattended system reports a heartbeat: launchd jobs check the scraper fleet, the ETL pipeline, and the article scheduler every 15 minutes and push a phone notification the moment a failure streak or stall appears. Alerts deduplicate on state transitions, remind daily while broken, and send a recovery note when healthy again. Silence means healthy, and silence is verified.

Big changes run as forged one-shot briefs: baseline git tags and a verified backup first, parallel recon agents next, then implementation against explicit acceptance criteria, closing with work reports committed beside the code. Multi-agent fan-outs handle the wide work, like auditing two dozen repos in parallel, while deterministic scripts handle the loops.

15 Safety & Quality Hooks

rm_guard Intercepts destructive deletions before they execute
sed_guard Prevents sed from corrupting data structures by running pattern substitutions that can't detect existing prefixes (e.g. doubling a prefix already applied)
config_guard Blocks any reads of .env files and writes to package scripts; enforces proper dependency management via poetry add or npm install
package_manager_guard Intercepts any direct write of a pinned version string (package==1.3.4) into a file; Claude habitually writes pinned versions straight into manifests, bypassing dependency resolution and lock file management entirely
