Production Infrastructure

Claude Code as a Service, deployed via Docker and Coolify.

I needed a production API that could generate social media copy for new content automatically, without API costs and without a human in the loop. Instead of calling the Anthropic API directly, I built a FastAPI + Celery service that runs the Claude Code CLI via subprocess inside Docker containers, deployed via Coolify.

Claude writes output to a temp file as structured JSON. FastAPI reads it, validates against a Pydantic schema, and retries automatically on schema failure. It is launched anytime content goes live.

services/claude_worker.py 
# app.py — FastAPI wrapping Claude Code CLI
MAX_RETRIES = 3

def call_claude_to_file(prompt, schema, model=None):
    output_path = f"/tmp/claude_{uuid.uuid4().hex}.json"
    full_prompt = f"{prompt}\n\nWrite JSON to: {output_path}\nFields: {schema}"
    result = subprocess.run(
        ["claude", "-p", full_prompt, "--dangerously-skip-permissions"],
        env={**os.environ, "CLAUDE_CODE_OAUTH_TOKEN": token},
        capture_output=True, text=True, timeout=60,
    )
    if result.returncode != 0:
        raise HTTPException(status_code=502, detail=result.stderr)
    return json.loads(Path(output_path).read_text())


@app.post("/social/copy", response_model=SocialCopyResponse)
def social_copy(req: SocialCopyRequest,
                api_key: str = Security(verify_api_key)):
    last_err = HTTPException(status_code=502, detail="All retries failed")
    for attempt in range(1, MAX_RETRIES + 1):
        try:
            data = call_claude_to_file(req.prompt, SCHEMA)
            return SocialCopyResponse(**data)  # 200
        except ValidationError as e:
            last_err = HTTPException(422, str(e))
        except HTTPException as e:
            last_err = e
    raise last_err  # 502 after 3 attempts
Content Pipeline

Autonomous content generation pipeline.

70+ virtual author profiles publish 6+ pieces of content daily with zero human intervention. Here is every stage.

1
Content Planning
Category-matched author profile is selected from 70+ profiles. Each profile has a defined voice, vocabulary range, sentence length targets, and topic affinity scores.
2
Generation
Claude generates the draft using a write-time prompt protocol that embeds the author's voice rubric directly into the system prompt. Per-author structural patterns are enforced before generation starts.
3
Anti-LLM Validation (18 checks)
Output runs through 18 validators before it is allowed to proceed. Catches patterns that make content sound generated rather than written.
em-dashes banned phrases (50+) staccato patterns orphaned micro-sentences passive overuse missing contractions transition word stacking hedging language listicle structure uniform sentence length
4
Voice Scoring
Content is scored across 10 dimensions against the author's profile: warmth, formality, vocabulary complexity, sentence rhythm, personal anecdote density, and more. Pieces below the threshold are regenerated.
5
Approval Gate
Validator pass + voice score above threshold = approved. Failed pieces loop back to generation with failure context added to the prompt. No human reviews individual pieces.
6
Publish
Approved content is written to the Django backend via internal API. Metadata, author attribution, category tags, and publication timestamp are set programmatically.
7
ISR Revalidation
Cloudflare cache and Next.js ISR are invalidated for the new content path, making the piece live on the Next.js frontend without a full rebuild.

4 PreToolUse Safety Hooks

rm_guard Intercepts destructive deletions before they execute
sed_guard Prevents sed from corrupting data structures by running pattern substitutions that can't detect existing prefixes (e.g. doubling a prefix already applied)
config_guard Blocks any reads of .env files and writes to package scripts; enforces proper dependency management via poetry add or npm install
package_manager_guard Intercepts any direct write of a pinned version string (package==1.3.4) into a file; Claude habitually writes pinned versions straight into manifests, bypassing dependency resolution and lock file management entirely
